# Catalogs

The `/admin/departments`, `/admin/positions`, `/admin/skills` and `/admin/languages` pages (PLAN S5.1–S5.4; KAN-96, KAN-98, KAN-100): the global lists of departments, positions, skills and languages, for Admin users. Each page lists, searches, sorts (by name; languages also by ISO code) and pages on the backend, and creates, updates and deletes one item. A department or position has a name only; a skill has a name and a category, and shows the category's type; a language has a name, an ISO code and a native name.

- Exports (`index.ts`): `Departments`, `Positions`, `Skills`, `Languages` (the page bodies) and `CATALOG_FIRST_PAGE` (below).
- Server render (PLAN D6, KAN-172): each route prefetches its first page (`CATALOG_FIRST_PAGE`: `firstPageVariables(DEFAULT_CATALOG_SORT)` of `@/shared/lists`, the same for all four) with `PrefetchQuery` (`@/shared/apollo/server`), and the admin layout prefetches `me` for `RequireAdmin`. The page's hook finds the rows in the Apollo cache, so the server HTML already has them and the browser does not ask again. Search, sort and page changes go to the backend from the browser. E2E: each catalog spec, "as the server renders it".
- Texts: `messages/en.json`, `pl.json` (namespace `catalogs`). `departments`, `positions`, `skills` and `languages` share their keys, so the shared parts take the namespace `catalogs.departments`, `catalogs.positions`, `catalogs.skills` or `catalogs.languages` (`CatalogNamespace`) and work for all four. `skills` has extra keys for its columns and the Category field; `languages` for the ISO and Native name columns and fields.
- Shared by all catalogs (everything except the GraphQL wiring and the skill and language forms):
  - `catalogs.types.ts`: `CatalogNamespace`, `CatalogItem` (`id`, `name`), `CatalogNameFormValues`.
  - `catalogs.constants.ts`: `CATALOG_SORT_FIELDS`, `DEFAULT_CATALOG_SORT` (name ascending, the first sort of every catalog page), `CATALOG_FIRST_PAGE`, `MAX_CATALOG_NAME_LENGTH` (100, as the backend), `CATALOG_SEARCH_MAX_LENGTH`.
  - `utils/`: `catalogNameSchema` (the name rules). A `CONFLICT` error is read with `readFailure` (`shared/failures`, kind `conflict`): on create or update the name exists; on delete the item is in use.
  - Hooks: `useCatalogNameForm` (the form), `useCreateCatalogItemForm(ns, create)`, `useUpdateCatalogItemForm(ns, update)`, `useDeleteCatalogItem(ns, remove)`: they take the catalog's mutation function and show the toasts and error texts. Save is enabled only when the trimmed name differs from the original (`hasChanged`). A delete of an item in use keeps the confirmation open and shows the "in use" text inside it (`error`); other delete failures close it and show a toast.
  - Components: `CatalogTable` (the Name column, optional `extraColumns` and the row menu), `NameFormModal` (one-field modal, kind `create` or `update`), `DeleteCatalogItemModal`, `CatalogPage` (`ListPage` + table + the Delete modal; each catalog passes its Create/Update modals in `modals` and opens them via `onCreate`/`onEdit`; after the only row of a later page is deleted it goes back one page, and shows the loading state, not the empty state, in between).
- Per catalog (`components/Departments/`, `components/Positions/`, `components/Skills/`, `components/Languages/`, the same shape): `useDepartments` / `usePositions` / `useSkills` / `useLanguages` (the list query through the shared `usePagedList`), `useCreateX`, `useUpdateX`, `useDeleteX` (each with its `.graphql` file), and `X.tsx`, which passes them to `CatalogPage`. Test data: `x.mocks.ts`, thin files over the shared factory `createCatalogMocks` (`catalogs.mocks.ts`, with its test).
- Skills only (`components/Skills/`): the Type and Category columns (`extraColumns`), `useSkillCategories(enabled)` (the Category options, loaded only while a modal is open), `useSkillForm` (name + category, `hasChanged` on the trimmed name or the category), `useCreateSkillForm`, `useUpdateSkillForm` and `SkillFormModal` (Name field + Category select). The type is not sent: the backend takes it from the category. `skills.mocks.ts` adds its own create, update and category mocks, as these send a category.
- Languages only (`components/Languages/`): the ISO column (sortable, `LANGUAGE_SORT_FIELDS.iso`) and the Native name column (hidden below the desktop width), `useLanguageForm` (name + ISO + native name; `hasChanged` on the trimmed values with the ISO code uppercase; the ISO input shows its letters uppercase with CSS only, so the browser keeps its cursor, undo and phone-keyboard input; the value is uppercased on submit), `useCreateLanguageForm`, `useUpdateLanguageForm` and `LanguageFormModal` (three text fields). A taken ISO code is a `CONFLICT` with `extensions.reason = "ISO_TAKEN"` (`readFailure` gives kind `conflict` and the `reason`; `ISO_TAKEN_REASON` is in `languages.constants.ts`) and shows under the ISO field; a `CONFLICT` without it means the name is taken. `languages.mocks.ts` adds its own create and update mocks, as these send three fields.
- Used by: the routes `app/[locale]/(app)/admin/departments`, `admin/positions`, `admin/skills` and `admin/languages` (`PageHeader` + the page). E2E: `e2e/catalogs/` (`skills.spec.ts` and `languages.spec.ts` have their own tests, as their seeds have more than one page and their forms more fields). `languages.spec.ts` has no "in use" delete test: no API gives a user a language yet, so the test cannot own that data; `Languages.test.tsx` (mocked `CONFLICT`) and the backend tests cover it until the user-languages ticket (S6.x) adds the E2E test.

## Notes (PR review of KAN-98, 2026-11-20)

- The general error inside a modal ("Something went wrong…", "Could not load the categories") is the shared `FormErrorMessage` (`@/shared/components`, KAN-100): `NameFormModal`, `SkillFormModal` and `LanguageFormModal` had the same `<p role="alert">` and `.error` rule three times.
- The Retry of the Category error ("Could not load the categories") is the shared `Button` with `variant="text"`, under the message (decided 2026-11-20). It is the standard pill button, so it is larger than a text link; the visible text is upper case, the accessible name stays "Retry".
- `useSkillCategories(enabled)` uses `skip: !enabled`. In Apollo Client 4 the loaded categories stay available after `skip` turns true, so the Category select keeps its options while a modal fades out. `useSkillCategories.test.tsx` checks this. If an Apollo upgrade makes that test fail, the Create modal will show an empty Category field while it closes.

## Notes (PR review of KAN-100, 2026-11-23)

- `useLanguageForm` compares the name with each run of whitespace as one space, like the backend `NormalizeSpaces`. The Department, Position and Skill forms (`catalogNameRule`) only trim, so "New York" for "New York" still enables Save there although the backend stores the same name. Fix with the shared-code refactor below.
- The language form hooks (`useLanguageForm`, `useCreateLanguageForm`, `useUpdateLanguageForm`) repeat the Skills and catalog form hooks. The planned shared-code refactor ticket merges them; change one set and check the other.
- The migration `20261123120000_languages_catalog_rules` stops on a unique-key error if the database has an ISO code in two letter cases ("en" and "EN"). The seed data has none; for other data, merge those rows first (backend `languages/README.md`). A merged migration is not edited.
- There is no E2E test for deleting a language in use: no API gives a user a language yet. Add it with the user-languages ticket (S6.x).
