# Verify email

The `/verify-email` page (PLAN S3.6, KAN-90): six code boxes, CONFIRM, RESEND with a countdown, and LATER. A new user lands here after [sign-up](../sign-up/README.md); the code comes in a mail.

- Exports: `VerifyEmailPage` (`app/[locale]/(auth)/verify-email/page.tsx` renders it and sets the translated page title).
- `components/VerifyEmailForm`: the form. `useVerifyEmail` holds the state: an empty or incomplete code shows its error after a submit; the code stays when the request fails; the failure message goes when the user types; the button stays locked while the request runs and until the redirect, so a request cannot be sent twice. After a good code the hook writes the answer (`SessionUser` with `isVerified: true`) into the cached `me` and goes to `/users`. `utils/` has `validateCode` (exactly 6 digits, a shape check only). `useVerifyEmail` reads a failed request with `readFailure` (`shared/failures`) and maps it: kind `invalid` with `reason` `CODE_INVALID`, `CODE_EXPIRED` or `CODE_USED`, and kind `tooManyRequests` (with `TOO_MANY_ATTEMPTS` or without a reason, the throttler) → a message; kind `conflict` with `ALREADY_VERIFIED` → leave the page. The meaning of a `reason` stays in this feature.
- The frontend never decides if a code is good: the backend answers on CONFIRM. The page reads `me` only to send a user who is verified already to `/users`; it never keeps the status itself.
- `components/ResendCode`: RESEND, its answer message and the countdown (`useCooldown`). The backend allows one code per 60 s (`RESEND_COOLDOWN`); the button waits 60 s after a sent code and after a `RESEND_COOLDOWN` answer. `useResendCode` reads the failure with `readFailure` (`shared/failures`): kind `tooManyRequests` (the cooldown, or the throttler without a reason) means wait, `conflict` with `ALREADY_VERIFIED` leaves the page. A new code clears the boxes. The countdown does not start when the page opens: right after sign-up the first RESEND shows "Please wait before requesting another code" and starts it.
- RESEND and LATER use the `ghost` button variant. The red `text` variant has about 2.5:1 contrast on the dark background (the minimum is 4.5:1); an earlier draft of this page found it with a Storybook accessibility test. Ask the designer before using `text` here.
- LATER is a link to `/users`. It changes nothing in the account; the backend still blocks what needs a verified email (`@Verified()`).
- Code boxes: [`OtpField`](../../shared/components/OtpField/README.md) in `@/shared/components`.
- Texts: `messages/en.json` and `pl.json` (namespace `verifyEmail`). The LATER link uses `Link` from `@/shared/i18n`, so it keeps the language.
- Tests: component tests next to the code, mocked GraphQL through `renderWithProviders`; E2E in [`e2e/verify-email`](../../../../e2e/verify-email) (the code is read from Mailpit). A successful RESEND is not in E2E, because it needs a 60 s wait after sign-up: it is covered by the `ResendCode` tests and the backend `verification.int-spec.ts`.
