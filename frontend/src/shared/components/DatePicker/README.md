# DatePicker

A date field with a calendar popup: [react-datepicker](https://github.com/Hacker0x01/react-datepicker) (PLAN §2.2) with our `Field` as its input, our own calendar header and our own CSS (the library's CSS is not loaded).

- Export: `DatePicker` (props: `label`, `value: Date | null`, `onValueChange`, `onBlur`, `ref`, `locale`, `labels`, `minDate`, `maxDate`, `name`, `helperText`, `error`, `disabled`, `required`) and the types `DatePickerProps`, `DatePickerLabels`.
- Controlled only. With React Hook Form, wrap it in a `Controller` and pass `field.value`, `field.onChange`, `field.onBlur` and `field.ref`.
- `locale` is the app language. The date-fns locale (`datePicker.constants.ts`) gives the month and weekday names. The date format (`DATE_FORMATS`) shows and parses typed dates: `en` MM/dd/yyyy, `pl` dd.MM.yyyy (decided 2026-11-05, PLAN D34). The week starts on Sunday in both languages, as the design draws it. `en` names are British English: US English names days with ordinals ("November 4th"), which fails axe.
- `labels`: the screen-reader texts, translated by the caller. react-datepicker's own texts are English only. The popup's name comes through `CalendarDialog` (a custom `calendarContainer`) and `CalendarLabelContext`.
- Calendar: month and year buttons switch to a month list or a year list (`useDatePicker` keeps the view). The picking steps run day → month list → year list (decided 2026-11-05): a day click saves the date and opens the month list, a month click saves it (day kept, cut to the month end) and opens the year list, and a year click saves it and closes the calendar. The month and year buttons are shortcuts into the second and third step. Every click saves at once, so the field and the form show the date while the calendar is still open. A click in the input while the month list or the year list is open closes the calendar (the lists have no way back to the days); the next opening starts on the days. In the day view the click only places the cursor, so typing works. In the day view the header arrows page months. In the month list and the year list they move the SAVED date by one month or one year (day kept, cut to the end of a shorter month; an empty field starts from the shown month), so the red selection travels and the value is saved at every click. The list pages itself when the date leaves it: December → January of the next year, the last year of a page → the next page. At `minDate` or `maxDate` an arrow is disabled (logic: `utils/datePicker.utils.ts`). The month list shows full month names. Hover is `--color-surface`, one step lighter than the options in a Select. The layout follows [date-picker-layout.png](../../../../../docs/images/date-picker-layout.png).
- Keyboard: typing a date works. The first Arrow Down moves into the calendar, then the arrows move by day or week, and Enter picks. Escape closes.
- `onBlur` runs only when focus leaves the field and its calendar. Mouse clicks in the calendar keep focus in the input (see `CalendarDialog`).
- The popup sits under the field, not in a portal: inside a clipping container (`overflow: hidden`), give it room.
- No clear button, by decision (PLAN D34): the user deletes the text by hand. An empty End Date means "Till now", which the page shows, not this field. A typed text that is not a date gives `null`, like an empty field, so the form shows one message for both (see `SampleForm.stories.tsx`).
- Start and end date pair: pass the start as the end field's `minDate` and the end as the start field's `maxDate`; an empty side sets no limit (story "Start and end date", tests in `DatePicker.test.tsx`).
- Used by: project and CV project forms (start and end dates). Values: [docs/design-tokens.md › Date picker](../../../../../docs/design-tokens.md#date-picker-ds).

## Known issues (KAN-78 review)

- The CSS of the month list, the year list and the red open-list header was written from the measured design picture and the tests. Nobody has looked at it in a real browser yet. Open the Storybook stories "Month list" and "Year list" in light and dark, and compare them with the picture. The weekday row shows three letters ("Sun"); the picture shows one letter ("S"). It is not changed because nobody asked for it.
- Dark theme: the open-list header uses the lighter error red (`--color-error-text`), not the drawn #C63031, which has 2.5:1 contrast on the dark fill.
- The calendar is 449px wide. The app shows the Device Error page below 768px ([docs/pages/09](../../../../../docs/pages/09-device-error-page.md), PLAN D28), so a phone-width check is not needed. The Settings page (15) mentions mobile: check the calendar there if that page ever gets a date field.
- The ref given to `ref` is read from the DOM by id once (`useElementByIdRef`). It is not refreshed if react-datepicker replaces the input. No bug is seen today. If it shows up, make the hook refresh the element. `OtpField` uses the same hook: run its tests after any change.
